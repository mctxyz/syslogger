# 日志名称目录

名称目录由 SDK 的接收活动建立，CLI 的 `--list` 读取该目录，用于查找项目、实例和组件身份；实际日志由 journal 留存。

## 开启目录

`CatalogEnabled` 默认关闭，开启后将实际使用的日志身份、描述和最近三个自然小时的接收量发布到固定的 `/var/lib/mct-syslogger`，与 `TMPDIR`、状态维护及指标出口配置独立。部署时先准备本机 `app` 账户，再使用配套 CLI 的独立子命令准备目录权限及专用 journal：

```sh
sudo mct-syslogger init
# 四个空间默认合计 5G，可独立调整其中一项。
sudo mct-syslogger init --journal-info-max-use 10G
```

初始化需要 Linux、systemd 245+、root 及已有的本机 `app` 账户。历史目录和配置由部署方手动处理，清理前先停止相关写入进程；容量、压缩和管理员配置保护见[部署说明](journal.md)。业务开启目录功能的示例：

```go
manager, err := syslogger.New(syslogger.Config{
    Project: "contract-listener",
    InstanceID: "mainnet-a",
    InstanceDescription: "主网事件监听",
    CatalogEnabled: true,
})
if err != nil {
    return err
}
defer manager.Close(context.Background())
rpc, err := manager.Register(syslogger.ComponentConfig{
    Name: "rpc",
    Description: "区块与日志获取",
    QueueCapacity: 512,
})
if err != nil {
    return err
}
rpc.Info("RPC 已连接", nil)
```

组件首次成功接收日志时通知后台建立目录记录，接收包含异步入队和同步开始发送；管理器初始化、组件注册及健康报告保持各自职责，名称目录由实际接收活动建立。容错初始化产生的结构化诊断使用 `syslogger_manager`，同样按成功入队进入目录。描述供目录展示，日志及指标继续使用原有身份。

## 清单与每小时接收量

清单按项目和实例保存 JSON，项目目录名为项目原文的 SHA-256 十六进制摘要，实例文件名为实例 ID 的 SHA-256 十六进制摘要加 `.json`。实例保存 `created_at`；组件保存 `name`、`description`、`created_at`、`last_active_at` 和 `log_counts`。固定长度路径兼容现有身份中的斜杠、空白及长项目名，CLI 用身份原文组织目录。

`log_counts` 按旧到新保存三个小时项，每项包含 `start_time`（该小时的实际起始时刻，UTC）和 `count`（该小时内的 SDK 成功接收量）。分桶使用设备本地时区的自然小时，SDK 和 CLI 应使用一致的设备时区。例如设备处于 `+08:00`，当前为 2026-11-06 13:25 时，展示 11 点、12 点和尚未结束的 13 点：

```json
{
  "log_counts": [
    {"start_time": "2026-11-06T03:00:00Z", "count": 120},
    {"start_time": "2026-11-06T04:00:00Z", "count": 240},
    {"start_time": "2026-11-06T05:00:00Z", "count": 35}
  ]
}
```

相同 `start_time` 的增量继续相加；新的小时起点标识独立计数段，超过窗口的小时淘汰，缺少活动的小时补零。每项数量为 `uint64`，达到最大值后自然回绕为零。包含异步入队和同步开始发送，后续发送失败或关闭时放弃的日志仍计入；编码、上下文、队满或关闭等接收前拒绝不计。该数量与 journal 当前留存条数分别解释。

日志调用线程在既有队列锁内更新当前小时增量，后台每 10 分钟取走并按小时起点合并文件快照；跨整点的同一批次保持各条日志原来的小时归属，失败窗口合回内存重试。同身份多个进程的增量在项目锁内合并，旧调用晚取得锁时也会保留已经写入的新小时。组件的创建时间、最后活跃时间独立于小时数量，静默三小时后仍可在一年身份保留期内显示。

项目和实例保持原有单行展示；组件首行在名称后显示完整本地最后活跃时间及 `每小时: 起点=数量 | 起点=数量 | 起点=数量`，小时起点包含月日、时分和时区偏移，数量使用逗号千位分组。时间列按选中组件名称的显示宽度对齐，描述另起一行与时间列对齐，不加表头。`--list --json` 保留 UTC 时间和完整整数精度，并按查询当时的窗口补齐三个小时。

静默文件保存最后一次成功同步的三小时快照，CLI 只读查询时按当前窗口将过期数量显示为零；下次文件写入再淘汰旧小时，不额外增加逐小时全目录重写。夏令时重复小时以实际 UTC 起点区分，缺失整点时采用该小时第一个实际存在的时刻，三个自然小时的实际时长可能受时区跳变影响。合并使用已观察到的最新小时作为水位；设备时间大幅回拨时，落在水位窗口之外的新活动数量不会保留，已淘汰的小时也不会恢复。

### 部署与重建

SDK、CLI 和读取目录 JSON 的消费方使用配套版本。清单按当前字段结构读取，未知字段或多个 JSON 对象明确报错，源文件保留给管理员处理。更新前停止相关写入进程，人工清理旧版本目录和配置，再运行 `sudo mct-syslogger init` 创建根目录；后续接收活动建立当前清单。仓库中已有的 `tools/bin/*` 需要另行重新构建，源码更新不会自动替换这些二进制。

## 权限与故障处理

名称根目录、项目目录、JSON 及项目 `.catalog.lock` 固定由 `app` 及其主 GID 持有。目录使用 `0755`，JSON 和锁文件使用 `0644`，普通账户只读；写入由 `app` 或具备相应文件操作权限的 root 进程执行。`init` 解析账户的实际 UID/GID 并创建根目录，SDK 以根目录的属主为身份来源，通过新对象的文件描述符设置属主。因此过渡期 root 程序创建项目目录、锁文件及原子替换清单后，后续 `app` 程序仍能继续维护。

发布和清理通过 [gofrs/flock v0.12.1](https://github.com/gofrs/flock/tree/v0.12.1) 协调项目文件锁，在锁内读取、合并小时增量并使用同目录临时文件原子替换。项目锁文件保持稳定，日志调用线程只维护内存活动，文件 I/O 在后台执行。systemd 配置由 root 管理，journal 存储由对应 journald 实例维护，与名称目录的所有权各自独立。

### 重复初始化

`init` 复用符合当前所有者、权限和 ACL 规范的根目录，已有子目录、清单和锁保持原状。根目录元数据不符合规范时明确报错，交管理员人工处理；SDK 对已有项目目录及锁的异常也直接报告。根目录缺失时再运行 `init` 创建。系统账户配置保持原样。

目录缺失、权限不足或发布／清理失败通过标准日志诊断；开启状态维护时，仅内置 `syslogger_manager` 因目录不可用而降级。业务组件健康、日志发送、指标出口及业务关闭结果保持独立。失败增量留在内存并按原周期重试；空闲周期也复查根目录，使初始化完成后的恢复不依赖新增日志。发布与清理分别恢复，注册及配置故障仍按各自条件恢复；关闭状态维护时只诊断，关闭目录功能时不检查。目录不可用期间，`--list` 可能为空或显示旧记录，已知身份仍可直接用于日志查询。

## 关闭与保留期

`Close` 在日志队列及同步调用收尾后完成最终同步并停止目录后台任务，保留未过期身份记录；异常退出可能丢失最近一次成功同步后尚未保存的增量。重启按小时起点继续合并仍在窗口内的计数，创建时间继续保留。组件按最后一次成功接收时间判断一年有效期，轮询本身不续期，其他组件的活动也不为静默组件续期；全部组件超过物理清理窗口后删除实例 JSON。宽限期内记录继续存续并合并仍有效的小时数量，过期记录实际移除后再次有日志时建立新记录。

SDK 每 10 分钟清理过期记录，物理清理额外保留一个同步周期，给过期前已成功接收、尚未刷盘的活动保留合并机会；合并按实际接收时刻判断生命周期是否连续。全部接入应用退出后暂停物理清理，后续 SDK 运行时继续。CLI 的 `--list` 始终按一年活动期限过滤过期项，物理宽限不延长显示期限；名称目录用于选择历史日志过滤条件，journal 日志仍按其自身留存范围查询，也可手动指定身份。目录历史数据与旧目录由部署方自行处理。
